# RULfuse codebase re-audit — 15 November 2026

**Assessment: functional research infrastructure, but not ready for design-freeze sign-off.**
The most consequential finding is a reproduced future-image leak in F0's padded training
batches. The selected F0 design and comparisons involving it need reassessment after that
defect is corrected. Gate 3 also deviates from the planned inner-training protocol and can
freeze a calibration that fails its coverage constraint. Passing tests do not cover these
failure modes.

This is an audit, not a remediation change. No application implementation, experiment
configuration, model weights, or scientific decision was changed by this audit. Only this
report, its reproduction script, and its evidence file were added. Real held-out test
results were not scored or unsealed. Synthetic tests exercise the seal and post-freeze paths.

Supporting files: [check results and source hashes](AUDIT_2026-11-15.evidence.json),
[synthetic reproduction script](audit_reproductions_2026_11_15.py).

## Confirmed findings, in priority order

### F01 — High / P1 / 9 out of 10: padded F0 image batches can read future photos

**Locations:** [fusion.py](../rulfuse/models/fusion.py#L318),
[sequences.py](../rulfuse/sequences.py#L248).

`collate` pads image times with zero. F0 counts every image time before the query time,
including padding, then uses that count to index the image-GRU states. For a shorter image
sequence, padding inflates the index and can select a state containing a photo that has
not yet become available. The validity mask controls GRU updates but does not correct this
lookup.

**Reproduced:** a batch containing two-photo and four-photo units gives the shorter unit
times `[10, 20, 0, 0]`. At time 5, F0 incorrectly marks the image expert present. The same
unit's prediction changes from **60.5373 s alone to 64.5329 s in the padded batch**.
Changing its time-20 photo changes its time-5 prediction by **0.41246 s**, with dropout
and feature noise disabled.

**Impact:** unequal photo counts occur across tools and augmented trajectories, so this
affects normal F0 multimodal training, not just an unusual deployment input. Single-unit
inference can remain causal while the learned model was trained through a leaking path.
Existing causality tests use a single sequence and miss this case. F1 does not use this
lookup; this finding does not establish the same defect in F1.

**Required action:** select the last valid, causally visible image by its actual position;
test mixed lengths, empty image sequences, dropped tokens, truncation, and batch invariance.
Then invalidate affected fits and reassess the relevant F0 comparisons and downstream reuse.
The audit establishes the defect, not the numerical size of its effect on historical runs.

### F02 — High / P1 / 8 out of 10: Gate 3 inner fits perform a new validation selection

**Locations:** [study.py](../rulfuse/study.py#L269),
[train.py](../rulfuse/train.py#L285),
[PROJECT_PLAN.md §7.2, step 10](../PROJECT_PLAN.md#L1001).

The plan requires each inner fit to train on six tools for the outer fit's selected number
of steps, **with no inner selection**, then predict the two held-out tools. The new code
constructs an inner pseudo-fold retaining the outer validation tool and calls the normal
`fit` loop. That loop evaluates the validation tool repeatedly, applies patience, and
restores its own selected checkpoint. It never reads the outer fit's selected step count
to set the inner budget. `heldout` changes output roles and skips diagnostics, but leaves
checkpoint selection active.

**Impact:** out-of-fold predictions and calibration are produced by a different protocol
than registered, with another adaptive use of the validation tool. Compute estimates based
on a fixed outer-selected budget also cease to apply. The new test that lean and full fits
have identical weights verifies the current behavior, not the planned fixed-step behavior.

**Required action:** implement an explicit fixed-step inner mode using each corresponding
outer fit's selected budget, with no inner early stopping/checkpoint search. Check that the
inner fit cannot run before that outer selection exists. If a different scientific protocol
is intended, document and approve that change before using its results.

### F03 — High / P1 / 8 out of 10: fit reuse does not establish identical inputs or implementation

**Locations:** [train.py](../rulfuse/train.py#L69),
[study.py](../rulfuse/study.py#L176), [study.py](../rulfuse/study.py#L285),
[train.py](../rulfuse/train.py#L262).

`fit_key` hashes `FitConfig` only. Cross-study matching checks the store string, config
key, validation unit, seed, and inner held-out list. It omits the encoder names/revisions,
resolved feature-cache signatures, implementation version, and a complete training-input
identity. An existing `DONE` fit is skipped without even checking the current configuration.
Resumed checkpoints likewise lack a checked run identity.

**Reproduced:** two study specs using different signal and image encoders generate the
same fit key; `find_identical_fit` returns the old source fit for the new study.

**Impact:** a changed encoder, corrected model, or edited study can silently receive old
weights and predictions. In particular, fixing F01 without changing fit identity can still
cause later studies to copy affected historical fits.

**Required action:** persist and verify a fit identity covering actual store, feature caches,
training/validation roles, seed, resolved configuration, and relevant implementation version.
Verify it on reuse, `DONE` skip, checkpoint resume, and aggregation. Invalidate old identities
when behavior changes.

### F04 — High / P1 / 8 out of 10: design freeze accepts calibration outside the required band

**Locations:** [gate3.py](../rulfuse/gate3.py#L272),
[gate3.py](../rulfuse/gate3.py#L402).

When no calibration candidate has coverage in `[0.85, 0.95]`, the decision chooses the
candidate nearest 0.9, sets `constraint_met=False`, and still returns `complete=True`.
`freeze` checks only `complete`, then writes a normal frozen design.

**Reproduced:** ten synthetic folds with candidate coverages of **0.20 and 0.30** yield
`constraint_met=False`, choose method c, and successfully produce a frozen design hash.

**Impact:** finishing computation is treated as passing the scientific gate. A frozen design
can therefore fail the project's stated uncertainty requirement by a large margin.

**Required action:** distinguish computation completion from gate acceptance and reject a
freeze when the coverage constraint fails, unless an explicit amended decision is recorded.

### F05 — Medium / P2 / 6 out of 10: CUDA resume does not restore CUDA random state

**Locations:** [train.py](../rulfuse/train.py#L292),
[train.py](../rulfuse/train.py#L376).

Checkpoints save and restore NumPy and CPU Torch random states only. GPU feature noise and
dropout consume CUDA random state, which is absent. In addition, loading every tensor with
`map_location=device` can put the saved CPU RNG tensor on CUDA before it is passed to the
CPU-only `torch.set_rng_state` API.

**Impact:** the documented interrupted-fit equivalence is demonstrated on CPU only. CUDA
resume cannot currently be certified as identical and may fail restoring the CPU state.
The missing CUDA state is confirmed by source inspection; the CUDA-specific runtime behavior
was not exercised because this environment has no CUDA device.

**Required action:** checkpoint/restore the relevant CUDA generators and keep the CPU RNG
state on CPU. Verify a killed-and-resumed GPU fit against an uninterrupted fit on Ruche.

### F06 — Medium / P2 / 5 out of 10: a valid dataset without images cannot build model inputs

**Locations:** [store.py](../rulfuse/core/store.py#L216),
[tokens.py](../rulfuse/tokens.py#L228).

The generic schema permits no images. Writing its empty image table produces no columns;
`build_fold_data` unconditionally accesses `images['unit']`, including for usage-only or
signal-only configurations.

**Reproduced:** a schema-valid three-unit signal dataset builds its store successfully,
then usage-only fold construction raises `KeyError: 'unit'`.

**Impact:** the adapter/core transfer contract does not cover a common supported modality
combination. The current toy transfer test always includes photos, so it misses this.

**Required action:** write empty tables with explicit schemas and test a genuinely image-free
dataset through feature preparation, fitting, and prediction.

### F07 — Medium / P2 / 6 out of 10: B6 reporting can ensemble seeds that were not requested

**Locations:** [omnifuser_rul/train.py](../rulfuse/omnifuser_rul/train.py#L103),
[omnifuser_rul/aggregate.py](../rulfuse/omnifuser_rul/aggregate.py#L59),
[omnifuser_rul/run_report.py](../rulfuse/omnifuser_rul/run_report.py#L529).

Excluding seeds from a per-fit training signature allows individual fits to be reused,
but the prediction loader then globs all seed directories and filters only that signature.
It does not restrict them to the reporting specification's requested seeds.

**Reproduced:** requesting seed `[0]` in a folder containing seeds 0 and 1 loads both.
Synthetic predictions of 100 and 300 are reported as an ensemble prediction of **200**,
instead of the requested seed-0 prediction of **100**.

**Required action:** filter loaded fits by the exact requested fold/seed membership and
validate consistent point membership before ensembling. Keep individual-fit reuse separate
from ensemble identity.

### F08 — Medium / P2 / 4 out of 10: automatic RULfuse reports omit the D28 disclosures

**Location:** [study.py](../rulfuse/study.py#L599),
[D28](../PROJECT_PLAN.md#L78).

D28 requires the final report to provide the per-tool mean, pooled-point MAE, and the result
without T4. The current study reporter produces per-tool averages only. It does not emit
pooled-point or leave-T4-out summaries. `summary.csv` does contain point counts and per-tool
MAE, so these MAE summaries can be reconstructed; they are not automatically disclosed.

**Required action:** implement those summaries in the final reporting path and test them
on unequal per-tool point counts. This is particularly relevant because the documented
family and learning-rate choice depends on T4's sparse window.

### F09 — Low / P3 / 3 out of 10: SLURM status omits completed inner fits

**Location:** [status.sh](../slurm/status.sh#L50).

Expected fits are counted from every manifest row, but completed fits are globbed only at
`arm/fold-*/seed-*/DONE`. New Gate 3 inner fits live one level deeper. A fully completed
default Gate 3 study would show **30/150** fits rather than 150/150.

**Required action:** calculate completion from the manifest's exact outer/inner destinations.
Add the planned fake-tree status test.

## Recommended order of work

1. Fix F01 and add mixed-batch causality checks. Decide which existing F0 runs must be
   regenerated before using them for further choices.
2. Fix F03 before any reruns or copying, so corrected code cannot silently inherit old fits.
3. Bring inner fits into the registered fixed-step protocol and make coverage failure
   prevent freeze. Revalidate Gate 3 after the affected training results are available.
4. Verify CUDA checkpoint resume on Ruche; correct the image-free and B6 seed-selection paths.
5. Finish the frozen final-evaluation/report pipeline, including D28 disclosures, then
   the planned importance/sensitivity workflows. Keep the D15 test seal in place.
6. Repair static checks, the status counter, and documentation; automate the lightweight
   checks in CI and record a reproducible dependency environment.

**Sign-off condition:** corrected causal training, verified fit provenance, a compliant
Gate 3 that satisfies its coverage gate, and a tested frozen final-evaluation path. The
current codebase does not yet meet those conditions.
